# Anas RDP Plugin

[简体中文](README.md)

Use a Windows remote desktop in an Anas sidebar or separate window. A pinned native IronRDP engine owns the connection and framebuffer in the plugin backend; pages provide canvas display and keyboard/mouse input. No separate gateway is required.

The desktop displays the remote cursor, including movement from model tools. Model moves use a short local animation without adding remote mouse events or changing screenshots. The server editor offers “Disable mouse animation”, unchecked by default. Local movement appears immediately, and the cursor stays at its last position when the local pointer leaves. Locking local input keeps the remote cursor visible; unknown positions and server-hidden cursors are not drawn.

Requires **Anas 3.3.13 or later** (plugin API 2), which provides the titlebar menus, window state and fitting-before-activation APIs used by this plugin. Upgrade the host before installing the plugin.

Moving rebuilds the presentation while retaining the original connection and unsaved input. Closing a desktop tab or window always keeps its connection in the background; there is no background-running option. Resuming the desktop reuses that connection. Explicit Disconnect, including the server context menu, and tool state `closed` end the connection and close the desktop. Only unexpected disconnections retain the desktop and reconnect controls. Connections are independent of conversations. The sidebar toolbar’s Move to separate window icon moves the desktop directly. The context menu can also choose a sidebar or window. Opening and moving do not write configuration; a new desktop without an explicit location uses the saved preference. Open desktops and running connections block profile editing. Stopping the plugin or quitting the host ends its connections.

Each profile keeps an initial resolution (1280×800 by default) and independent “Adapt resolution in windows” and “Adapt resolution in sidebar” preferences, both off by default. After connection and confirmation of server support, both toolbars offer a resolution menu with common sizes and the configured custom size. Its bottom “Adaptive resolution” checkbox applies to the current location and immediately saves the preference to the profile; moves, reconnections and application restarts preserve it. Choosing a resolution changes neither this checkbox nor the saved initial size. In a separate window, selection restores a normal window and resizes both the window and remote desktop; in the sidebar, it changes only the remote desktop. With adaptation enabled, separate windows update the remote resolution only after a user resizes their border, maximizes or enters fullscreen; moving, changing displays and programmatic fitting do not change it. Sidebars adapt about 300ms after their area changes settle. Disabling adaptation retains the current remote size. Hidden or transferring pages do not resize, and resizing never reconnects. While support is unknown or unavailable, or after a dynamic resize failure, the same window button performs “Fit window to desktop” locally; the sidebar resolution menu is hidden. Failures are reported without clearing saved adaptive preferences.

The sidebar toolbar and separate-window titlebar provide “Input text”. Compose multiline text with the local IME, then click “Input to remote” or press `Ctrl/⌘ + Enter`; plain Enter inserts a newline, and sending does not append a remote Enter key. Long text is split at Unicode character boundaries and sent sequentially with acknowledgements and progress. Duplicate submission and local desktop input are blocked while sending. Cancel stops only unsent batches. Failure retains the original, confirmed progress and remaining text, warns that input may be partial, and never automatically replays it. Only complete success clears and closes the dialog; page handoff preserves the draft.

Before becoming visible, separate windows restore the normal content-area size remembered by the live plugin session, or use the configured size when none is recorded, before adaptation starts. Window size, display and position survive sidebar moves and closing/reopening a window; fullscreen, maximized and sidebar sizes or sidebar resolution changes never overwrite them. Disconnecting clears this memory. Initial and restored sizes may exceed the display. Windows return to the recorded display when available, otherwise the current screen; dragging out a tab takes precedence over the remembered position. Separate windows display at most one remote pixel per CSS pixel and scale down when needed. CSS pixels differ from physical screen pixels when system or application scaling is not 100%. Remote applications may not fit very narrow sidebars.

Clipboard support is off by default for each server; enabling it reveals the clipboard toggle. Each new connection starts with sharing off. Connections can enable sharing independently, and moving or retaining a desktop in the background preserves its switch. Only the active desktop synchronizes new content: a separate window must be foreground; a sidebar desktop must be selected and its tab, content or toolbar must be the current interaction region. Clicking the chat area, hiding the sidebar or switching tabs pauses synchronization; hovering does not activate it. Inactive connections retain published copies for pasting and finish existing file transfers. A newly active connection takes over new synchronization without disabling the other switches. Manually disabling sharing still waits for file transfers to finish and does not retract copied text. Tooltips indicate syncing, waiting for activation or finishing a transfer.

Windows supports bidirectional file and folder copy/paste: copying exchanges metadata, and pasting reads file contents on demand. Remote files are not downloaded in advance, and source files are never moved or deleted. Intel macOS tests cover bidirectional text, local-folder uploads, active-connection switching, and transfer cancellation/disconnection. An upload may remain busy for about a minute after cancellation. Direct remote-file paste into Finder is not implemented; Windows multi-connection switching and local Explorer paste/cancel still need verification. Images and rich text are not supported.

## Use

Screenshots return images by default. With `save: true`, the same PNG is also saved under the host data directory at `tmp/anas-plugin-rdp/screenshots/`; metadata includes an absolute `saved_path` on success or `save_error` while retaining the image on failure. These temporary files are excluded from backups and may be removed by host cleanup. Saving requires a host that provides `tempDirectory`.

Install the ZIP or select `PLUGIN.json` in the complete directory in Anas Settings → Plugins. Add a server from the top plugin menu and select its opening location. Double-click a row or select Start to connect. Profile editing and connection pages are separate: saving never connects, and connecting never implicitly saves a profile. See the bundled [user guide](docs/USER_GUIDE.md) for installation, password protection, certificates, and languages.

Supports 200 saved profiles and four concurrent connections. Basic keyboard/mouse input is provided. Direct desktop key mapping does not support local IME composition; use the “Input text” dialog; remote IME and complex-shortcut behavior depends on the target application. Audio and multiple displays are not provided.

The plugin exposes five tools: `list` queries servers and runtime status, `profile` manages saved configuration, `control` changes runtime state, `screenshot` captures the desktop, and `input` sends input. All server operations use stable `profile_id`; `session_id` only identifies the current connection. Profile input and output fields use snake_case. `profile.action` is `get/add/update/delete`; add requires `changes.host`, update/delete require the latest revision, and update merges only supplied fields. Running connections, open desktops and active edits block profile changes and deletion. Optional `control` fields are `state`, `location`, `ui_locked` and `reset_input`; omitted fields stay unchanged. foreground connects and shows the desktop (not OS focus), background connects and closes its desktop, and closed disconnects and closes the desktop. `location: sidebar|window` requires foreground and never saves the preference. Use `ui_locked: true/false` to lock/unlock and `reset_input: true` for an explicit reset; without state these require an existing connection and never connect implicitly. closed cannot combine with other operations. Combined control runs connection, input lock, input reset, then presentation. Inspect `ok`, actual status and `applied`; failures include `failed_step/error`, and completed effects are not rolled back. The same profile reuses its connection and page; disconnected desktops can reconnect in place. Each operation stays bound to its selected connection and never redirects remaining input to a replacement. `list` includes configuration, revision, connection and desktop status, including disconnected pages and resources whose profile was removed externally. `view` is null when no desktop exists.

Connections use saved passwords and existing certificate trust. Input supports Unicode `text`, named keys, chords, and inter-action delays. One `input.actions` sequence can enter text then press Enter or Ctrl+Enter; sequences are validated and sent as requested. Raw down/up events can span calls; the plugin neither tracks nor automatically clears tool-held input. Text uses paced small batches; input lasting more than 10 seconds can continue in the background. An input deadline stops only the remaining steps, not the connection or plugin backend.

The Reset input button and `control({profile_id, reset_input: true})` tool share one implementation: RDP Synchronize with toggle flags 0 releases ordinary keys and modifiers and turns off Caps Lock, Num Lock, Scroll Lock and Kana Lock, and releases the left, middle and right mouse buttons at the last known pointer position. It runs only on explicit invocation, never on tool or conversation completion. It interrupts any pending tool input sequence on that connection (the original call returns `RDP_INPUT_RESET`) without changing the connection or local input lock.

The desktop toolbar and separate window titlebar provide Lock local input. When selected, local keyboard, mouse and wheel input are blocked while display and model tools remain available; unlocking, disconnecting and closing remain available. Models use `control({profile_id, ui_locked: true/false})`; `control` and `list` return `ui_locked`. The lock belongs to the live connection and survives moves, background recovery and conversation completion. New connections start unlocked; it is not saved in configuration. Models explicitly unlock after continuous work, and users can unlock manually at any time. The lock does not exclude other tool callers, and manual unlocking does not stop an executing tool.

Windows x64 tests cover model connection, queries, screenshots, disconnection, keyboard/mouse input, page handoff, desktop display, and connection reuse across turns. macOS x64 tests cover the new tool input APIs, local input locking, page handoff, background recovery, cross-turn connection reuse, and shutdown cleanup. Exact Unicode tool input content has also been verified on the remote desktop. See [testing notes](docs/TESTING.md).

Clipboard availability follows its own channel state. When the desktop is visible but CLIPRDR negotiation is incomplete, the disabled switch shows “Clipboard channel initializing”. Protocol readiness enables the switch; sharing still requires an explicit click.

## Development

Requires Node.js 24 and Rust 1.94.1. `upstream.lock.json` pins IronRDP; `native/Cargo.lock` locks native dependencies.

```sh
npm ci
npm run typecheck
npm run build
npm test
npm run test:ui
```

`dist/` is the installable local-platform directory. For distribution, run `npm run package` and `npm run verify:package`. CI builds shared UI and three native targets, combines a universal ZIP, and retains dependency licenses.
